# セキュリティ・信頼性

## 扱うデータ

- 団体基本情報
- 団体内部資料
- 過去申請書
- 財務関連資料
- 申請内容
- AI生成物

## データ分離

全データにorganization_idを持たせる。

NPO AのデータはNPO Aの処理でのみ参照可能とする。

AIプロンプトにも不要な他団体データを入れない。

## AIへのデータ送信

必要最小限のデータだけを送る。

可能な対策:
- 直接識別情報の除去
- 必要箇所だけ抽出
- Providerごとのデータ利用条件確認
- 原文ログの無制限保存を避ける

## 監査ログ

重要操作を記録する:
- ログイン
- 資料アップロード
- AI実行
- 申請書生成
- 承認
- 提出
- 結果変更

## AI出力の信頼性

重要条件はAI要約だけを根拠にしない。

UIに情報源、取得日時、募集要項、AI分析日時を表示する。

## 表現上の境界

「申請可能」「採択される」と断定せず、
「募集要項上、条件A/B/Cに該当。条件Dは要確認」
のように根拠と不確実性を示す。
